One Night, Two Checks

codeintel-csrf-token-analyzer verifies the implementation of CSRF protection mechanisms in web application code, focusing on token generation and validation. In the code as it stands that means pattern matching over Python files.

Generation Patterns

The generation check looks for the named token assigned from a generate token call, from secrets.token_hex, from os.urandom, or from uuid.uuid4, including the same value shapes assigned into a session entry under the token name.

Validation Patterns

The validation check looks for an if line in which a request form or POST field is compared with the token using not equal, in either order, with subscript or get access. The two checks are reported separately, and a file may hold either one without the other.

Usage, the True Line at Full Size

python3 main.py SOURCE_CODE_PATH [--token_name NAME] [--form_field FIELD] [--exclude PATH ...]

That line matches the argument parser in main.py: one required positional path, then the three named options. No second line is needed beside it and none is invented.

The Five Parameters

-hShow help message and exit.
source_code_pathPath to the source code directory or file. Required.
--token_nameName of the CSRF token (default: csrf_token).
--form_fieldName of the CSRF form field (default: csrf_token).
--excludeList of files or directories to exclude.

Two facts from the parser stand beside the list at the same size. The token name and the form field must each be a plain identifier, a letter or underscore followed by letters, digits, or underscores, because both names are placed into the search patterns as raw pattern text, and a run with any other shape of name is refused with an error and exit 1. A path that is neither a file nor a directory is likewise refused with an error and exit 1.

Read the Log Lines, Not the Exit Code

A Python file containing a token generation call and a form field comparison against the token reports both generation and validation logic found. A file with neither reports both as not found, and still exits 0. The exit code does not distinguish a clean file from a file with no CSRF logic, so read the log lines, not the exit code, for the result.

Found Across the Tree Is Not Found in One File

A directory run pools its two findings across the whole tree, so generation in one file and validation in another reads as both present even when no single file does both halves.

Exit 0 Proves Nothing Either Way

Only files ending in .py are read, so token handling written in any other language or in a template is outside the check altogether, however sound or unsound it may be.
